# Srujana Stage 1: The "Zero to One" Micro-Challenges

Welcome to PRODIGY! Stage 1 is about proving you can use AI tools as a force-multiplier to spot a real problem, build a quick prototype, and communicate your solution clearly. 

**Goal**: Complete 3 micro-challenges.  
**Duration**: 4–8 weeks (self-paced, ~5-10 hours/week)  
**Prerequisites**: A laptop, internet connection, and curiosity.  

---

## 🎯 Challenge A: The Problem Canvas (Week 1-2)

Don't start with code. Start with a problem.
1. Pick a domain you care about (e.g., Agriculture, Healthcare, EdTech, Local Business).
2. Use an AI tool (Gemini, Claude, ChatGPT) to interview "synthetic personas" and research a specific, painful problem in that domain.
3. **Deliverable**: A 1-page Problem Canvas documenting:
   - Who is the user?
   - What is their exact pain point?
   - How are they solving it today?
   - Why is the current solution broken?
4. **Submission**: Create a GitHub repository for your project and add the canvas as `problem_canvas.md`. Open an Issue titled "Challenge A Submission" and tag your mentor/peer.

## 🛠️ Challenge B: The AI-Assisted Prototype (Week 3-5)

Build a rapid, "duct-tape" prototype of your solution.
1. Use AI coding assistants (Cursor, GitHub Copilot, or Claude/Gemini) to help you write the code. Focus on the core functionality, not the polish.
2. The prototype must demonstrate the "Monkey-First" principle—solve the hardest part of the problem first, even if the UI is ugly.
3. **Deliverable**: Working code pushed to your GitHub repository + a 2-minute Loom/YouTube screen recording demonstrating how it works.
4. **Submission**: Open a Pull Request in your repo with the code and video link.

## 🗣️ Challenge C: Peer Review & Reflection (Week 6-8)

Innovation requires feedback and articulation.
1. Review another student's Challenge A or B submission. Leave constructive, kind, and specific feedback on their GitHub Issue/PR.
2. Write a 500-word reflection on your own prototype: What worked? What failed? What did the AI get wrong? What would you do differently in Stage 2?
3. **Deliverable**: Written reflection document + link to the peer review you provided.
4. **Submission**: Add `reflection.md` to your repo and close your initial Issue.
